# 任务实时同步手工测试

## 环境与准备

本次实现尚未发布，请在本地测试。前端入口为 http://localhost:3000/，API、Redis、live 服务也需要运行。正常情况下保存后约 1–2 秒更新；标题需等自动保存完成。断线后的重连可能因退避多等待几秒，周期补偿为 30 秒。

准备两个标签页 A、B，同账号即可；验证多人协作时，使用两个已加入同项目的成员账号。项目访客目前不接收项目级实时推送。测试时不要刷新接收页，否则无法判断是自动同步还是刷新加载。

## 可靠增量协议补充验收（2026-11-11）

本轮在上述同一本地环境创建 MCPT-12，独立详情修改、接收页观察，结束后经 UI 删除并确认接收页移除，项目恢复列表。已确认：

- 标题变化且不参与筛选/排序时，接收页走 `sync/changes` 加 `sync/entities`，没有重拉全部列表页。
- 状态变化命中分组依赖时，请求带 `sync_window=1&sync_entity_mode=changed&sync_depth=1`，以服务端结果校准 ID 顺序、分组和 counts。
- 表格接收远端标题，打开预览显示最新值；关闭 live 后详情仍能通过 REST 日志补拉更新。
- 修复布局首次加载被旧同步订阅抢断的竞态，新增回归并实测表格、看板、列表加载完成。

最终自动测试：前端 28 文件 312 项、后端日志与窗口 62 项、live 同步 10 项通过；React Doctor 98/100 无诊断。深分页、过期游标、回滚、并发提交与撤权依靠自动测试，本轮没有在 UI 创建千条任务或进行真实双账号验收。代码未提交、未部署。
