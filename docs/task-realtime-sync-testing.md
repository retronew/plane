# 任务实时同步手工测试

## 环境与准备

本次实现尚未发布，请在本地测试。前端入口为 http://localhost:3000/，API、Redis、live 服务也需要运行。正常情况下保存后约 1–2 秒更新；标题需等自动保存完成。断线后的重连可能因退避多等待几秒，周期补偿为 30 秒。

准备两个标签页 A、B，同账号即可；验证多人协作时，使用两个已加入同项目的成员账号。项目访客目前不接收项目级实时推送。测试时不要刷新接收页，否则无法判断是自动同步还是刷新加载。

本地已有的入口：

- [MCP 测试项目任务/看板](http://localhost:3000/wuzuo/projects/f3f3930b-3a4b-4cf6-a935-a46838e131d0/issues/)
- [该项目归档任务](http://localhost:3000/wuzuo/projects/f3f3930b-3a4b-4cf6-a935-a46838e131d0/archives/issues/)
- [工作区全部任务](http://localhost:3000/wuzuo/workspace-views/all-issues/)
- [我的工作](http://localhost:3000/wuzuo/profile/00386379-402e-4f34-a085-61a0862b8a58/)
- [本地项目列表](http://localhost:3000/wuzuo/projects/)

这些链接指向本地 wuzuo 工作区，不能用于线上 software 工作区。请新建一条带“同步测试”前缀的任务，记录其编号，并仅修改这条任务。此前验收的 MCPT-8/9 已清理。

## 核心场景

| 场景           | A 页面和操作                                              | B 页面和预期                                                           | 本轮证据                                   |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------ |
| 状态与看板分组 | 项目任务页，新建测试任务，从 Todo 改为 In Progress        | 同项目看板：卡片自动从旧分组移到新分组，计数最终一致，不重复出现       | 已双标签页实测，约1.2秒                    |
| 标题           | 点击测试任务进入详情，修改标题，失焦并等“已保存”          | 项目列表或看板：同一任务标题自动更新                                   | 已实测                                     |
| 优先级         | 列表/看板修改测试任务优先级                               | 另一页打开该任务详情，属性自动更新                                     | 已实测，约1.2秒                            |
| 创建           | 在项目页“添加工作项”创建新测试任务                        | 另一页保持同项目列表/看板，新任务自动出现                              | 已实测                                     |
| 归档           | 将测试任务设为 Done，再在“更多操作”中归档并确认           | 普通列表自动移除；已打开的归档列表应自动加入                           | 普通列表移除已实测；两个列表同时打开可补测 |
| 取消归档       | 进入归档任务页，测试任务“更多操作 → 恢复”                 | 普通列表自动重新出现；归档列表移除                                     | 已实测                                     |
| 删除           | 对本次创建的测试任务执行“更多操作 → 删除”，核对编号后确认 | 另一页列表自动移除，分组计数最终一致                                   | 已实测，约1.4秒                            |
| 通道恢复       | 由开发者停止live；A修改优先级后保存，再恢复live           | B开始保留旧值，恢复连接后自动显示最新值，无需刷新；断线不影响A普通保存 | 已实际停启服务验证                         |

## 扩展覆盖与推荐补测

以下入口已接入统一列表刷新或任务实体刷新，但本轮没有逐项做完整双账号UI验收。请在同一条测试任务上验证。

| 场景                        | 验证路径与步骤                                                                  | 预期                                                                       |
| --------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 负责人、标签、开始/截止日期 | A打开任务详情修改属性；B保持列表或该任务详情                                    | 对应属性自动更新                                                           |
| 筛选命中变化                | B项目任务页 → 筛选，仅看“负责人=我”或指定标签；A修改测试任务使它满足/不满足条件 | 自动加入/移出B当前结果，保留B的筛选条件                                    |
| 排序                        | B选择优先级或日期排序；A修改测试任务相应属性                                    | B按当前排序重新排列                                                        |
| 周期任务                    | 项目菜单 → 周期 → 打开周期任务页；A在任务详情添加/移除该周期，B停在周期页       | B任务成员关系及可见分组计数更新                                            |
| 模块任务                    | 项目菜单 → 模块 → 打开模块任务页；A在任务详情添加/移除该模块，B停在模块页       | B任务自动加入/移出模块列表                                                 |
| 项目视图                    | 项目菜单 → 视图 → 打开已有任务视图；A修改任务属性                               | B按视图现有筛选、排序、分组更新                                            |
| 全部任务                    | B打开工作区“视图 → 全部任务”；A修改项目内测试任务                               | B对应行或卡片更新，跨项目汇总保持筛选                                      |
| 我的工作                    | B打开“我的工作”，选择指派给我；A将测试任务分配给B或移除负责人                   | B结果加入/移出，现有页面选项保留                                           |
| 侧边详情                    | B从任务列表打开侧边详情；A修改同一任务属性                                      | B侧边详情更新；远端删除/撤权后清理实体并关闭相关弹窗                       |
| 快速连续修改                | A连续修改状态、优先级；B保持看板                                                | 最终与A最后成功保存结果一致，无重复卡片、无长期旧状态                      |
| 未保存编辑                  | B输入标题但暂不失焦；A修改其他属性；随后B失焦保存                               | B输入不被静默重置；结束编辑后继续同步，属性以服务端保存结果校准            |
| 恢复前台                    | B切到后台；A修改任务；再回到B                                                   | 自动校准，后台期间不承诺即时渲染                                           |
| 权限撤回                    | 使用测试账号，B打开测试项目；管理员从项目设置移除B权限                          | 推送前或周期重查后停止该项目通知，清理缓存；无权限用户收不到项目变更元数据 |

## 当前范围外

- 文档页面的通用属性同步、在线成员和光标、离线写入队列尚未新增。
- 任务描述继续使用原有 Plate/Yjs 协同。本引擎的详情刷新主动保留描述，不以整体替换描述的方式同步。
- 评论、活动、附件、关系等后端变更会触发任务失效通知，但前端未新增这些独立集合的完整重拉适配器；不要把它们全部视为实时同步已完成。
- 未完成真实双账号、多实例部署与线上验收；本轮真实UI证据来自同一账号两个标签页。
