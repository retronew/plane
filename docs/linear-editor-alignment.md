# Linear 编辑器对齐记录

## 范围（2026-11-04）

按用户最新要求：保留 Plate/Slate，优先对齐 Linear 的内容渲染 UI 和功能菜单；参考并补齐 Linear 能力，现有额外能力暂时保留供用户单独审查。不是删除富文本底层或迁移为 Markdown 源码存储。优先使用 Plate 官方插件和输入规则。

## 业务覆盖范围

此次相对 HEAD 没有新增业务入口迁移；以下入口此前已使用 Plate，本次由共享组件修改统一生效，实际菜单仍受各入口权限、只读模式及 disabledExtensions 限制：

- Web RichTextEditor：任务详情及侧边预览、任务创建、Intake、项目描述、模板、描述历史展示。
- Web LiteTextEditor：评论创建/编辑/展示、通知侧栏内容。
- Web StickyEditor：便签正文。
- Pages editor-body 与 DocumentEditor：页面正文及历史展示。
- Space RichTextEditor：公开任务描述（原本只读）；Space LiteTextEditor：公开评论。

任务详情有内容时仍应直接编辑，不存在按正文非空禁用编辑的设计。协作尚未同步、权限不允许时整体只读；无法识别的旧 HTML 保留块局部不可编辑。2026-11-04 已通过 ego 在 FS-30 实际复现：外层编辑器 contenteditable=true，但无属性 div 包裹的两段正文被转换成 html_opaque，内部 contenteditable=false；根因是内容兼容转换，而非编辑权限。修复须同时覆盖 HTML 导入与已经存入 Yjs 的普通容器保留块。已存协作内容采用服务端 CAS 转换后发布，避免多个客户端自行拆块产生重复正文；带自定义属性、样式或未知嵌入的内容继续保守保留。

FS-30 已在 ego 实际完成键盘输入、Backspace 删除测试文字、自动保存及刷新验证：恢复为2个可编辑段落和2处粗体，html_opaque 为0，正文恢复原样；实际保存产生正常的描述活动记录。

## 实测依据

通过 ego 在 Linear 的 Test 团队「【测试】01 电商平台改版」项目创建 [TES-17](https://linear.app/newretro/issue/7fec65f7-63ad-446b-9a3f-53a4abab2948)。确认输入 `# `、`**粗体**` 即时渲染；粘贴列表、待办、引用、代码块、表格可解析；保存重开后格式保留。页面编辑层具有 ProseMirror DOM，不据此推断其私有后端存储或是否使用 Tiptap。

测得默认正文 15px/24px、字重450；H1为22px/29.6px、字重600；列表项间距6px；代码正文12px/20px；代码和表格圆角6px、细边框。项目使用自己的主题色和字体，保留明暗主题与大字号设置。

## 保留待审查的能力

以下功能在本系统现有实现中存在，本次观察的 Linear 菜单中未发现直接对应项；不据此断言 Linear 全部入口都不支持。

- 文字颜色与背景色调色板。
- 段落左对齐、居中、右对齐、两端对齐。
- 字体族与字号显示设置。
- H4–H6 标题（Linear 此次斜杠菜单仅见 H1–H3）。
- Callout 提示块。
- 单元格合并与拆分。
- 图片精确宽度与对齐设置。

以上均未删除。保留现有 HTML/JSON/Yjs 内容契约及资产、提及和权限语义。

- 复制代码成功/失败均有单元测试；浏览器环境剪贴板权限拒绝，已确认显示失败反馈，不声称实际系统剪贴板复制成功。
- 回归覆盖 HTML/legacy JSON/Markdown 公式往返、列表内公式、链接内行内公式，以及生产 NodeId 开启时的 Yjs 双端同步与撤销。

## 实现选择

优先沿用 Plate 官方输入规则、Toggle、Math、CodeBlock 和 Markdown 插件。未发现可用的官方 Mermaid 插件，因此使用 Mermaid 官方库懒加载，strict 模式生成 SVG 后以图片显示，禁用图内回调/链接交互。图表沿用已有代码块存储，不增加数据库字段或更换协同协议。旧 Tiptap 兼容代码仍保留，未做依赖清理；新增内容的 JSON 往返保证针对正式 Plate adapter。
