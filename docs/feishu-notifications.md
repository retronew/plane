# 飞书个人通知

## 应用配置

创建飞书企业自建应用，开启机器人能力，申请 `im:message:send_as_bot`（以应用身份发消息）权限，将目标用户加入应用可用范围，并发布可用版本。使用应用机器人，不是群 Webhook 自定义机器人。

在 Plane 实例后台的「飞书通知」页面填写 App ID、App Secret。Secret 加密存储，接口不返回密钥内容；保存时留空表示保留。检查配置只验证应用凭据，不能证明目标用户可接收消息。

将页面显示的回调 URL 原样加入飞书应用安全设置。回调格式：

`https://<Plane 域名>/api/users/me/integrations/feishu/callback/`

此域名必须把 `/api/` 转发到 Plane API，并携带用户登录 Cookie。个人中心返回地址为 `/settings/profile/notifications/`。在本地前后端分端口部署时，不能仅把回调指向未代理 API 的前端开发服务器；需配置同源代理后再实际授权。

配置项：`FEISHU_ENABLED`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_VERIFICATION_TOKEN`、`FEISHU_ENCRYPT_KEY`。后三项均加密且只写，留空保留。当 `SKIP_ENV_VAR=0` 时由环境变量管理，后台禁止修改。部署时执行迁移及 `configure_instance` 初始化配置键，重启 API、worker 和 Beat。不要在已有环境重跑 setup.sh。

## 消息卡片与交互回调

八类业务通知使用对应标题和颜色，展示工作项编号、名称、当前状态、优先级和截止日期；活动通知显示操作人及变更摘要，评论通知提供评论锚点。普通工作项卡片按现有权限与工作流提供状态选项；待审批卡片按当前用户所属分支提供批准和拒绝按钮。待审批时不显示普通改状态操作。

在飞书「事件与回调」中获取 Verification Token 和 Encrypt Key，先保存到 Plane，再选择将回调发送到开发者服务器，填写后台显示的卡片回调地址并添加新版 `card.action.trigger`：

`https://<Plane 域名>/api/integrations/feishu/cards/`

此接口与个人绑定 OAuth 回调不同，必须公网 HTTPS 可达且 `/api/` 正确转发。配置 Encrypt Key 开启请求加密。地址校验使用 challenge；普通交互严格校验原始请求签名、时间窗口、Verification Token、App ID、操作者租户及 open_id、绑定账号、消息 ID 和动作签名。未配置完整回调凭据时，卡片仅提供跳转。

个人消息不需要群权限，可关闭「允许被其他机器人邀请进群」。应用发布后配置才生效；更新自己发送的卡片沿用应用消息权限。不要订阅旧版 `card.action.trigger_v1`，也无需接收群聊天消息。

每条卡片的快捷操作有效期为创建后24小时，动作参数固定。用户点击后立即收到「已受理」提示；Beat 每10秒扫描等待至少5秒的动作，worker 再执行审批或状态更新，通常需等待5–15秒加业务执行时间。现有 runner 的前置步骤仍在数据库事务外执行，提交时再次核验权限、绑定、源状态/版本和工作流。重复点击或并发点击不同选项只会受理一个动作；失败或已过期时通过 Plane 页面重新处理。卡片不自动替换为新的审批或新的状态上下文。

执行结果与业务提交保持原子性，worker 中断可恢复；完成后通过消息 PATCH 更新原卡片，卡片刷新失败单独重试，最多6次，不重复执行业务。失去项目访问权限后仅更新简短结果，不再显示实体详情。审批按钮的 `confirm` 字段保留，但飞书客户端的二次确认行为需真实应用联调；服务端授权不依赖此弹窗。

协议参考：[新版卡片回传交互](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-callback-communication)、[签名和加密](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)。

## 用户绑定

用户登录 Plane 后，在个人中心 → 通知中绑定飞书账号。绑定使用独立 OAuth 授权与 PKCE，不改变 OIDC 登录绑定；发送使用应用 tenant token，用户访问令牌不持久保存。更换 App ID 后需重新绑定；仅轮换同一应用 Secret 不需要重新绑定。

绑定成功后，开启个人飞书渠道，并发送测试通知。测试按钮成功表示已入队；最近投递状态显示发送结果。用户必须在应用可用范围内，且未拒收机器人。

## 偏好规则

- 渠道：站内、邮件、飞书。全局渠道关闭具有最高优先级。
- 事件：属性、状态、完成、评论、提及、到期提醒、待审批、新 Intake。
- 默认：站内和邮件开启，飞书关闭。旧邮件五字段及提醒/审批/Intake的旧偏好继续兼容。
- 每渠道可选择统一使用全局设置，忽略局部例外；局部记录保留。
- 允许例外时：项目个人偏好 > 工作区个人偏好 > 全局默认。
- 局部设置「继承」移除该项覆盖。返回有效值和来源，便于判断实际生效规则。
- 项目到期提醒还受 `remind_in` 和 `remind_feishu_enabled` 控制。管理员允许发送不覆盖个人关闭。
- 验证码、密码重置等账户事务邮件不受业务通知设置影响。

## 投递与故障

普通活动、提醒、审批分别接入统一偏好。飞书采用持久投递表，事件/用户/渠道唯一约束，Beat 每30秒扫描。发送前复核绑定、偏好、成员资格、实体有效性，以及提醒日期/负责人和审批状态/角色。

超时、限流等可重试故障采用退避和稳定 UUID。首次尝试时间在网络请求前持久保存；超过55分钟停止自动重试，避免跨飞书一小时去重窗口重复投递。此时 `delivery_window_expired` 表示无法安全自动重试，不能据此断言此前消息未送达。

解绑、关闭实例通知或更换应用会取消未发送记录。已经提交给飞书的请求无法撤回。
