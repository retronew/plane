# 工作区周期

工作区导航的「周期」打开 `/:workspaceSlug/active-cycles/`。按项目排列当前周期，展示负责人、剩余天数、燃尽／燃起图和状态统计，并链接到项目周期详情。图表复用 Recharts、Select、Avatar、Logo、Button 和通用工具提示；点击带色线标记的统计行可以显隐对应曲线。

## 权限与范围

`GET /api/workspaces/:slug/active-cycles/` 要求活跃工作区成员或管理员身份，同时要求用户在项目中仍为活跃成员或管理员。公开项目不自动纳入，工作区管理员不绕过项目成员条件。访客、停用成员和非成员不能取得对应快照，也不会通过拒绝的请求触发采集。

只展示未删除、未归档、已开启周期功能的项目中，`start_date <= 当前时刻 <= end_date` 的未删除、未归档周期。日期按项目时区分桶；剩余天数为距离结束时刻的完整 24 小时数，向下取整，不足一天显示 0 天。

## 真实每日快照

`CycleProgressSnapshot` 保存周期、项目、工作区、项目本地日期、真实采集时刻 `observed_at`、采集时区和六种任务数量。周期与日期有唯一约束，数量必须满足总数等于五种状态组之和。

复用现有 Celery worker、beat 和任务活动投递：

- 每 15 分钟对当前周期分批采集，每批最多 100 个周期；没有人打开页面也能采集。
- 任务新增、更新、删除及周期任务关联变化，经现有 `issue_activity` 投递触发所属项目的采集。定时采集还覆盖没有投递活动的修改。
- 打开工作区周期页或该周期快照接口，也会保存一次当前真实观测。
- 同一天更新为最新真实观测，跨日后不回写旧日期。日期使用实际执行时刻计算，延迟执行／重试不会冒充先前的时刻。
- 停机漏采、部署之前及其他没有记录的日期均为缺口。迁移不回填，不根据当前任务、完成日期或活动日志伪造每日快照。

历史记录是该日期最后一次实际采样的结果，不承诺一定采到午夜最后一刻。通过 `observed_at` 可以判断实际采样时间。周期结束后保留已采记录，不在结束之后补造“最终一天”。

旧的 `Cycle.progress_snapshot` 继续用于周期转移任务的结算结果，不作为每日历史使用，也不覆盖活跃周期的实时统计。

## 统计与图表

- 任务、状态、周期关联必须同属项目和工作区；排除删除的关联、删除／归档／草稿任务及 Intake 待处理任务。
- 总数包含已取消任务；有效范围 = 总数 − 已取消，待完成 = 有效范围 − 已完成。取消数独立展示，不算完成。
- 每一天的范围、待完成、已完成和进行中均取当天真实快照。以后增减范围、取消或重新打开任务，不改变旧快照。燃起图直接使用当天完成数，不从今天的范围反推过去。
- 理想线使用完整周期日期与对应范围，在结束日到达目标，不多加一天。统计栏显示今天的真实数量。
- 横轴从首次真实观测开始；缺失的历史日期使用 null，曲线及差值填充不会跨缺口连线。仅一条记录时显示数据点。未来不预测实际值，只有理想线和当前范围参考线延伸。
- 实际与理想曲线间使用当前领先／落后状态的浅绿／浅红填充；隐藏任一曲线同步隐藏填充。辅助填充不作为工具提示里的独立统计值。燃起图的其他状态展示待完成数。
- API 日历采样约 368 个点以内，保留周期边界及今天；稀疏采样在前端补 null 断点，避免将未知天数画成连续实绩。

## 接口与并发

工作区接口新增 `progress_chart`（日期到真实快照或 null）、`chart_start_date`、`chart_end_date`。保留 `completion_chart`，其中待完成数也仅来自真实快照，缺失日期为 null。

`GET /api/workspaces/:slug/projects/:project_id/cycles/:cycle_id/cycle-progress/` 返回按日期排序的真实快照数组，也可读取已结束周期。权限与工作区周期页相同，不提供 POST／PATCH 写入或客户端补历史的入口。

所有采集入口复用同一过滤规则。采集先按固定顺序锁周期，再读取任务和时钟，以批量 upsert 保存同日记录；避免并发旧观测覆盖新观测。查询和写入按页／批执行，不逐卡发请求。

工作区分页默认 10、最多 25 个周期，保留稳定排序、15 秒超时、手动重试和权限失效时隐藏旧内容的行为。

## 部署

迁移 `0133_pin_workspace_cycles` 首次固定周期菜单；迁移 `0134_cycle_daily_progress` 只创建快照表及约束，不回填数据。应用迁移后，让 worker 和 beat 加载本版本代码，现有 beat 会注册每 15 分钟任务。任务模块在 `CELERY_IMPORTS` 中登记，不依赖额外调度服务或线上 Plane 接口。

已有的项目周期分析／侧栏进度仍按其现有接口工作，本次不把那些回推数据冒充为每日快照。
