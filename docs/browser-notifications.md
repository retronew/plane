# 浏览器系统通知

PLANEBUG-55 在个人设置 → 通知 → 浏览器通知中提供本账号、本浏览器的通知开关。开关默认开启；浏览器权限仍需用户点击“允许通知”授权。拒绝授权后只提供浏览器站点设置指引，不重复申请。开关保存在 IndexedDB，其他标签页通过 BroadcastChannel 刷新显示；实际投递每次重新读取持久设置。

首次进入有权访问的工作区时，浏览器支持通知、开关开启且原生权限尚未决定，前台页面自动显示一次 Plane 站内引导。引导和设置共用授权入口，只有点击“允许通知”才调用原生权限请求；“稍后”、取消或关闭不会更改开关和权限。Web Locks 保证同源标签页只有一个进入展示流程。前台弹窗完成打开动画，或用户主动操作引导后，才按浏览器来源与 Plane 账号保存展示标记；页面在此前离开或进入后台则释放资格，由其他可见标签接管。标记不按工作区重复。旧版本在渲染前写入的标记不能证明弹窗已展示，不用于新流程；不影响已有通知开关或浏览器权限。存储异常不阻塞工作区使用。

## 行为与范围

- 需要至少一个打开的 Plane 标签页处于对应工作区；同步新站内通知（普通和提及两流），继承站内接收权限与 `in_app` 偏好。
- 各数据流第一次成功读取只建立基线，不弹历史记录。关闭后重新开启建立新基线，不补发关闭期间消息。刷新、Worker 重启和页面间接管沿用已有基线。
- 以创建时间及该时间的通知 ID 集合识别新事件；使用现有通知 URL 的 `browser_feed=true` 模式，通过签名的 `(created_at, id)` keyset 游标补齐。该模式保留已读、归档与稍后提醒的行，防止并发状态变化移动分页边界；展示前由 Worker 排除这些行。游标绑定账号、工作区和提及流，错误游标返回 400。现有收件箱的默认查询和分页行为不变，分页失败不提交不完整水位。
- 已读、归档、稍后提醒中的事件不展示。展示不会自动标记已读。系统通知优先显示站内快照中的工作项标题；没有结构化标题的通知（如每日摘要或仅带目标 ID 的记录）使用通用标题。正文继续使用通用文案，不显示评论、描述或摘要内容。系统通知可能在锁屏展示工作项标题，已在授权引导与设置中提示。
- 普通工作项、审批和需求收集使用通知捕获时的工作区及实体 ID 生成地址；摘要与缺少目标信息的消息回退到通知页。点击时重新核验当前账号，优先聚焦已有标签。通知 Worker 不控制工作区页面，而是向标签发送跳转消息；页面核对 Worker 来源、当前账号和同源目标后自行跳转。没有可用标签接收时尝试打开目标页。
- 页面每 15 秒唤醒一次 Worker，同一账号与工作区最多每 30 秒进行一次成功同步。失败在后续唤醒重试。浏览器会节流或冻结后台页面，不能保证固定延迟。
- 仅切到后台的标签页仍可接收，但可能延迟。关闭该工作区的所有 Plane 标签页或退出浏览器后，不再接收新的系统通知；站内消息仍保留，重新打开后可能在下一次同步中收到期间积压的提醒。无需 Web Push 或第三方浏览器推送服务。

## 方案选择

| 方案                                 | 评估与选择                                                                                                                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Notifications API                    | 标准系统通知入口，必须遵守站点权限和用户手势要求。实际展示使用 `ServiceWorkerRegistration.showNotification()`，兼容无需常驻页面的点击事件。                                                                        |
| Service Worker                       | 同一个脚本目录作用域注册共享投递 Worker，处理 message 和 notificationclick；不安装 fetch handler、不缓存应用资源、不接管根作用域的旧 PWA worker。Worker 可以被浏览器终止，下一次消息会重新唤醒；不依赖常驻定时器。 |
| SharedWorker                         | 适合共享连接，但并不解决持久通知点击与重启后的去重。当前无需额外常驻连接，不另加一层 Worker。                                                                                                                      |
| Web Locks                            | 使用来源级命名锁串行执行通知同步和投递，避免标签页以及 Worker 新旧版本并行处理。缺少锁能力时停止系统通知，保留站内通知。                                                                                           |
| IndexedDB                            | 保存按账号、工作区和开关版本隔离的水位、去重 ID 和设置。不保存通知正文。重启后沿用记录。                                                                                                                           |
| BroadcastChannel / broadcast-channel | 原生广播仅用于设置显示同步。第三方库支持 leader 选举，但其消息选举降级在计时器节流、CPU 饱和时可能出现双 leader；不用于严格投递互斥，因此不引入。                                                                  |
| Comlink                              | 项目已有依赖，但单次请求/响应仅需 MessageChannel，无需引入 RPC 代理。                                                                                                                                              |
| Workbox                              | 主要解决离线缓存与路由，本次 Worker 不缓存网络请求，无需引入。                                                                                                                                                     |

兼容性采用运行时能力检测：安全上下文、Notifications API、Service Worker、Web Locks 和 IndexedDB 缺一不可。无相关 API、权限拒绝或存储失败时保留站内通知，设置页提供状态或错误反馈。移动 Safari 等平台可能额外要求安装到主屏幕或受系统策略限制；能力存在仍不代表 OS 会实际显示通知，需在目标浏览器与操作系统上实测。

## 并发与故障语义

所有系统通知由同一 Service Worker 展示。页面带账号和工作区请求同步；Worker 在同源 Web Lock 内验证打开页面、登录状态、通知权限和偏好版本，再读取普通和提及流。

投递前先持久化事件水位，再调用系统展示，提供“至多一次尝试”语义。此顺序避免浏览器终止 Worker 后重复提示；若恰好在持久化后、系统显示前崩溃，或系统展示失败，则该提示可能丢失，原通知仍在站内通知页。浏览器通知没有与 IndexedDB 共同提交的事务，不能承诺严格的 exactly-once 可见投递。

账号切换、页面关闭、工作区切换或开关版本变化时停止旧请求后续投递。通知点击后再次验证账号。浏览器权限本身按来源共享，不代表其他 Plane 账号也开启了本地偏好。

## 验证

自动化测试覆盖初次基线、相同时间戳、分页失败、普通与提及、双页面同时唤醒、共享锁、Worker 重启、页面关闭接管、账号/工作区隔离、已读与归档排除、开关关闭重开、OS 展示失败、网络失败与点击跳转，以及设置 UI、权限申请与首次站内引导。

Worker 测试使用模拟浏览器 API，不能代替真实多标签和 OS 通知。开发环境为 `http://localhost:3000/`；验收应覆盖真实评论和提及、同事件不重复、关闭一页后的接管、关完所有页期间不再投递，以及通知点击和权限。
