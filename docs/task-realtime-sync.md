# 任务实时同步

对应 PLANEBUG-37，包含服务端通道（PLANEBUG-38）、前端接入（PLANEBUG-39）及集成验收（PLANEBUG-40）。2026-11-11 已在本地完成可靠日志、增量实体与服务端窗口校准改造，尚未提交或部署。

## 数据流

任务写入与工作区变更日志在同一数据库事务内提交 → Redis `plane:sync:v1` 唤醒事件 → live WebSocket → 浏览器按游标读取持久日志 → 合并变更字段与任务 ID → 实体批取或服务端窗口校准 → MobX 原子更新实体、分组、分页和计数。

WebSocket 是低延迟唤醒通道，REST 变更日志承担恢复职责。首次接入先固定日志基线，再读取当前窗口，随后重放基线之后的变更；客户端仅在该批变更应用成功后推进游标，不以 WebSocket 消息或实体接口的水位跳过尚未应用的日志。

数据库和既有 REST 权限仍是事实来源。事件不包含标题、描述等任务内容；任务描述继续沿用已有 Plate/Yjs 协同。

## 服务端

- `GET /api/workspaces/<slug>/sync/access/` 使用现有会话认证，返回工作区及可订阅项目 ID。
- `LIVE_BASE_PATH + /sync/workspaces/:workspaceSlug` 是独立 WebSocket 通道，要求 Cookie、受信任的精确 Origin 和有效工作区成员身份。
- 服务端消息为 `ready`、`invalidate`、`resync`、`access_revoked`，协议版本为 `1`。`ready/resync` 附带 `project_ids`；项目变更通知带 `project_id/event_id`，可选 `issue_ids`。
- 建连、推送前和每 30 秒核验权限；并发同会话核验合并。访客不订阅项目级推送，避免项目内任务可见范围不同带来的元数据泄露；当前仅项目角色至少为成员的用户订阅。
- 原生 WebSocket ping/pong 检查存活；浏览器无需发送应用消息。连接清理会释放定时器、Cookie 引用和待发事件。
- Django signals 覆盖任务及标签、负责人、周期、模块等关联变动；共享 QuerySet 覆盖 `update/bulk_create/bulk_update`，成功写请求中间件作为补充。
- 同事务持久记录 `WorkspaceSyncEvent`，工作区游标行锁保证提交顺序；事务回滚同时回滚日志，包含批量写入和保存点边界。提交后才发送 Redis 唤醒；请求兜底只补充未被模型记录覆盖的项目。
- `GET /api/workspaces/<slug>/sync/changes/?cursor=…&limit=…` 返回权限过滤后的事件、下一游标和 `has_more/reset_required/project_ids`；游标会跨过不可访问事件，不返回其元数据。无 cursor 的请求建立当前基线。
- `GET /api/workspaces/<slug>/sync/entities/?ids=…` 有界批取当前可访问实体，返回 `issues/removed_ids/cursor`；包含归档实体，排除删除和草稿。该 cursor 不用于推进客户端重放进度。
- 公共列表 GET 支持 `sync_window=1&sync_entity_mode=changed&sync_depth=N`，保留原权限、筛选、排序和分组。响应 `sync_window.results` 为有序 ID 树，`entities` 仅包含指定变更实体，沿用分页元数据；未知 ID 再批取实体。超限返回 `reset_required`，不伪装成完整截断结果。
- Redis 发布超时受限，失败后短时熔断；普通 CRUD 不依赖广播成功。持久日志由后台任务重试发布，浏览器前台定时补拉提供独立恢复路径。

## 前端

`SyncEngine` 将连接和订阅路由与具体任务视图分离。每个订阅提供稳定 key、可选项目 ID 及刷新函数。

- 同 key 订阅去重、150ms 合并事件；同步快照跨 key 串行应用，避免详情和列表的旧快照交错覆盖。请求进行中又收到事件时，在结束后再校准一次。卸载会取消正在执行的订阅，隐藏/断连释放旧 generation 队列，失败或挂起的旧请求不阻塞新一代同步。
- 实体快照不再使用 `updated_at` 判断是否可应用：缓存可能含浏览器乐观更新时间，不能与服务端时间直接比较。新旧请求由取消、revision、订阅生命周期与同步队列控制。
- 指数退避重连，收到 `ready/resync` 唤醒日志重放；仅前台每 30 秒补拉变更。页面隐藏、离线或 pagehide 时关闭同步 WebSocket、取消在途查询和定时器；再次可见且在线时重连并按原游标补齐。REST 自身认证成功后也可恢复同步，不因 WebSocket 持续不可用而阻塞补偿。
- 当前实际取过数据的列表才订阅。已知字段变化与当前筛选、排序、分组及 scope 依赖不相交时，仅批取并合并实体；结构变化请求服务端 ID 窗口校准，沿用已成功应用的查询参数和已加载深度，不在客户端重写业务筛选器。
- 服务端窗口按最深分组的首 N 页返回，保留原 per_page 和后续分页位置，原子替换权威 ID 顺序与 counts。未知字段、日志重置、深度或窗口超限时回退已有完整范围刷新。页面卸载和切换视图清理订阅，历史缓存不持续刷新。
- 详情对当前任务并发读取实体、评论、活动、关系、子任务，再经取消/revision/可见性校验后统一提交；实体 expand 同步链接、附件、表情。空集合覆盖旧集合，按需补齐父任务计数及未知状态/标签/成员字典。403/404 清理实体与集合，预览及弹窗关闭，独立页显示不可用态；远端归档后普通独立页进入归档详情。
- 普通子任务属性更新也将父 ID 纳入通知，父详情重读子任务与状态分布；跨项目父子 ID 按其各自项目发送。重置校准刷新并替换涉及项目的状态/标签字典，覆盖已缓存项的改名、改色和删除，跨项目窗口还包含上一窗口涉及的项目；精确普通任务更新仍只补取未知字典。
- 编辑弹窗读取实时共享实体，只合并未修改字段并保留 dirty 输入；保存仅提交实际修改字段，避免用打开时的旧快照覆盖远端属性。属性预加载不再因翻译函数变化重复请求或连续报错。
- 本地任务相关写请求暂停远程刷新并中断旧列表请求；响应 revision 防护阻止写入前的 GET 重新覆盖数据。写请求完成后的下一任务恢复，留出调用方 store reconciliation 时间。
- 输入期间暂缓远程刷新，失焦后继续校准。未保存内容不被静默重置；此机制不提供属性级 CRDT 或离线合并。

## 运行与发布

复用现有 `REDIS_URL`、live `API_BASE_URL/CORS_ALLOWED_ORIGINS/LIVE_BASE_PATH` 和 web `VITE_LIVE_*` 配置，无新增依赖。新增数据库迁移 `0171_workspace_sync`，需要先迁移，再启动新版 API、worker/beat、live 和 web。开发库迁移按 `docs/development.md` 的 local stack 流程执行，测试使用隔离的 `plane-test`。

部署需要更新 API、后台 worker/beat 和 live/web，以便所有写入进程加载 signals/QuerySet hook。浏览器已有构建仍需载入新版 web。代理必须保留 `/live` 下的 WebSocket Upgrade 与会话 Cookie；CORS Origin 需包含实际前端来源。

## 一致性边界

Redis Pub/Sub 自身不持久，可靠补偿由数据库日志和 outbox 重试承担；原始 SQL 仍绕过模型 hook。游标只在当前页面内存保留，重新载入页面重新建立基线。后台页面不持续拉取；每 30 秒前台补拉用于最终一致，不承诺故障期间的 2 秒延迟。

窗口差量减少实体传输，服务端仍执行原有权限、筛选、排序、分组及 counts 查询，并非常驻订阅的物化 Live Query。窗口最多 20 页、5000 个成员，超限完整校准；SQL partition/count 仍可能扫描完整结果。项目访客尚不接收实时推送。未完成真实双账号、多实例部署或线上验收，不能将本地同账号多标签页结果等同于这些环境。
