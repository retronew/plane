# 个人每日工作摘要

入口：个人设置 → 通知 → 每日工作摘要。默认关闭，与项目单条到期提醒分别配置。

用户可选择个人时区下的发送时间、每天或周一至周五发送、站内/邮件/飞书渠道、工作区与项目范围、统计分组，以及是否附带明细和发送全零摘要。范围为空表示所有当前可访问的项目，统计仅包含当前分配给自己的工作项。

## 统计与投递

- 本期完成：固定 `[period_start, period_end)` 内完成且当前仍处于完成状态的工作项。
- 本期新增分配：该周期内建立、当前仍有效的负责人关系。
- 当前未完成、已逾期、今日到期、即将到期：以生成时的状态和个人当地日期为准。即将到期不含今天，可选 1–30 天。
- 分组有重叠，不能直接相加。已完成、取消、归档、草稿、删除或失去访问权限的工作项不进入催办分组。
- 周一摘要覆盖上个发送周期以来的周末进展。首次启用、配置或时区变更以新起点开始，不补发历史消息。停机漏发合并为最新周期，旧待发周期失效。
- 每用户每周期一条 `DailyDigest`，每渠道一条独立投递记录，失败退避重试。站内摘要挂在一个仍可访问的所选工作区收件箱。
- 渠道遵循个人全局渠道与 `daily_digest` 事件偏好；飞书需要实例启用和账号绑定。摘要是个人全局事件，不提供项目级摘要事件例外。
- SMTP 已接受邮件后、数据库提交前进程崩溃仍可能造成重复邮件，不能保证严格 exactly-once。

## 接口与预览

- `GET/PATCH /api/users/me/daily-digest/`：读取或部分更新配置，`timezone` 只读，来自用户个人设置。
- `POST /api/users/me/daily-digest/preview/`：空请求体，使用已保存配置，只读生成预览，不发送通知。
- 只返回所选分组，每组数量为全量，明细最多 100 条；飞书为消息大小限制进一步截断。界面默认展示每组 3 条，支持展开。
- 修改设置会顺序保存，已显示预览保留为旧快照，需点击预览刷新。失败时还原到最近一次确认的配置。

## 部署与验证

新增迁移 `0170_personal_daily_digest`，仅建配置、周期和投递表，默认不开启任何用户的摘要。先运行 migrator，再更新 API、worker、Beat 和前端；共享包变动需重建相关前端。无需修改环境文件。

Beat 每分钟执行 `plane.bgtasks.daily_digest_task.dispatch_daily_digests`，worker 执行 `send_daily_digest`。生产部署遵循 [部署工具](../deploy-artifacts/README.md) 或 [本地镜像部署](local-image-deployment.md)。

后端回归覆盖 `plane/tests/contract/app/test_daily_digest.py`、`plane/tests/unit/utils/test_daily_digest_schedule.py`，并搭配原有到期提醒、渠道分发测试。始终在 `plane-test` 隔离栈执行。真实邮件和飞书测试需明确授权，测试后恢复用户的发送开关和通知偏好。
