# Plane 团队规范

在通过 Plane MCP 创建或修改任何内容时遵循以下规范。如果项目根目录有 `.claude/plane.md`，其中的规定优先于本文。

## 工作项

- **标题**：动词开头，说清楚要做成什么，不超过 60 字。例：「修复登录页在 Safari 下白屏」，不写「登录问题」。
- **描述**（Markdown）：
  - 背景：为什么要做（一两句）
  - 要做的：可验证的条目，用 `- [ ]` 列出
  - 验收标准：怎样算完成
  - 相关链接：设计稿、PR、文档
- **优先级**：
  - `urgent`：线上故障或阻塞他人，当天处理
  - `high`：本周期必须完成
  - `medium`：本周期计划内（默认）
  - `low`：有空再做
  - `none`：未评估
- **负责人**：创建时不确定就留空，不要随意指派他人；“分配给我”传 `me`。
- **截止日期**：只有真实的外部期限才填，不要用截止日期表达优先级。

## 状态流转

Backlog（待规划）→ Todo（已排期）→ In Progress（进行中）→ In Review（评审中，如果项目有）→ Done（完成）/ Cancelled（取消）。

- 开始动手时改为“进行中”状态组（`started`）。
- 提了 PR 但未合并，保持进行中或评审中，不要提前改为完成。
- 只有“已完成”或“已取消”的工作项可以归档。

具体状态名以项目为准，先用 `project` 工具 `action="states"` 查看。

## 分支与提交

- 分支名：`<type>/<工作项编号>-<简短英文描述>`，如 `fix/WEB-123-safari-login`；type 用 feat / fix / chore / refactor / docs。
- PR 标题以工作项编号开头：`[WEB-123] fix: ...`。

## 安全

- 删除、批量归档、批量修改之前，先列出将受影响的工作项并等待用户确认。
- 不要修改他人负责的工作项的负责人或截止日期，除非用户明确要求。
