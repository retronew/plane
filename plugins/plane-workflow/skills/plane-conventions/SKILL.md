# Plane 团队规范

在通过 Plane MCP 创建或修改任何内容时遵循以下规范。如果项目有明确的团队规范，优先遵循该规范。

## 执行边界

先遵循 Plane 团队规范。没有可用 Plane MCP 时只草拟，不宣称读取或写入成功。调用参数以当前工具 schema 为准。

先调用 `workspace(action="list")` 定位目标；歧义时询问。除该发现调用外，每次读取、分页、写入及核验都显式传 `workspace_slug`，同时携带目标项目和对象标识。跨工作区分别查询、分别分页并标明 slug 与项目来源；不得使用历史默认工作区，不得在无权限时切换工作区重试同名对象。

列表按返回的 cursor、next_page 或 has_more 连续分页，直到结束；如果达到客户端预算、权限受限或某页失败，明确标注仅覆盖已读取范围，不把部分数据当作全量排名、计数或规划依据。不要猜测分页参数。

写入前展示具体目标与变更，获得用户明确确认；已有明确授权仅在原范围内沿用。沉默、空消息或回车不算确认。任何步骤失败立即停止依赖它的后续操作，报告已成功、失败和未执行部分；结果不明时先读取核验，避免重复创建。写后读取核验，只报告已证实的结果。

## 工作区定位与权限

- 先调用 `workspace(action="list")` 列出当前令牌可访问的工作区，按用户的名称、slug 或链接自动定位；有歧义时询问。跨工作区查询分别调用、分别分页，并标明工作区名称/slug 与项目来源。
- 定位后每次工具调用显式传 `workspace_slug`（含读取、搜索、分页、写入及核验），避免同名项目与重复工作项编号串区。各流程示例中的 `<目标 slug>` 必须替换为已定位的工作区 slug。
- `workspace(action="list")` 无需 slug；其他工作区操作必须显式提供 `workspace_slug`。缺失时先 list 定位，仍不明确则询问，不使用请求头或历史工作区默认值。个人 token 可跨有权限的工作区，workspace-scoped token 不得超出绑定工作区；每次调用仍校验成员资格与项目权限。
- 写入前核实目标工作区、项目、对象和权限，展示带工作区来源的具体方案并确认授权；已有明确授权可沿用原范围。目标未确定先询问；无权限时拒绝该目标，不切到其他 workspace 重试同名对象或绕过限制。

## 工作项

- **标题**：动词开头，说清楚要做成什么，不超过 60 字。例：「修复登录页在 Safari 下白屏」，不写「登录问题」。
- **描述**（Markdown）：
  - 背景：为什么要做（一两句）
  - 要做的：可验证的条目，用 `- [ ]` 列出
  - 验收标准：怎样算完成
  - 相关链接：设计稿、PR、文档
- **优先级**：
  - `urgent`：线上故障或阻塞他人，当天处理
  - `high`：本周期必须完成
  - `medium`：本周期计划内（默认）
  - `low`：有空再做
  - `none`：未评估
- **负责人**：创建时不确定就留空，不要随意指派他人；“分配给我”传 `me`。
- **截止日期**：只有真实的外部期限才填，不要用截止日期表达优先级。

## 状态流转

Backlog（待规划）→ Todo（已排期）→ In Progress（进行中）→ In Review（评审中，如果项目有）→ Done（完成）/ Cancelled（取消）。

- 开始动手时改为“进行中”状态组（`started`）。
- 提了 PR 但未合并，保持进行中或评审中，不要提前改为完成。
- 只有“已完成”或“已取消”的工作项可以归档。

具体状态名以项目为准，先用 `project` 工具 `action="states", workspace_slug="<目标 slug>"` 查看。

## 分支与提交

- 分支名：`<type>/<工作项编号>-<简短英文描述>`，如 `fix/WEB-123-safari-login`；type 用 feat / fix / chore / refactor / docs。
- PR 标题以工作项编号开头：`[WEB-123] fix: ...`。

## 安全

- 删除、批量归档、批量修改之前，先列出将受影响的工作项并等待用户确认。
- 不要修改他人负责的工作项的负责人或截止日期，除非用户明确要求。
